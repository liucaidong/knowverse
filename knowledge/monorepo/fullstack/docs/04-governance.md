# 04｜从小型演示迁移到 Rush / Nx / Turbo

当前仓库用 pnpm + TypeScript 项目引用就可以完成包管理、类型构建与最小 CI。`tools/affected.mjs` 教授了反向依赖传播，但不替代成熟调度工具的 task graph 和远程缓存。

- **pnpm-only**：最容易审计，适合包少、CI 时间短、发布简单的阶段。缺点是任务缓存与发布编排要自行设计。
- **Turborepo**：当跨任务缓存带来清晰收益，且现有构建脚本有稳定输入/输出时再加；远程缓存的正确性依赖配置，不能仅看缓存命中率。
- **Nx**：复杂任务图、项目图导航和依赖边界是重点时优先评估。新版受影响分析要仔细区分项目级与任务级变化。
- **Rush**：当严格变更治理、多版本策略和大组织发布流程成为主要矛盾时评估。额外配置与维护成本可能超过小仓库收益。

迁移原则：**先测量后引入**。记录冷构建时间、增量构建时间、幽灵依赖数、CI 失败率；任何引入都要提供对照实验，而不是只凭工具热度。

实践任务：故意把 `node:fs` 加入 `packages/domain/src/index.ts`，运行 `pnpm check:boundaries`；随后恢复并将该测试加入 Pull Request 阶段。
