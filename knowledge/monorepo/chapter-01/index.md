# 工具能力矩阵与选型

> 来源：按可检索历史会话线索整理，部分表达为知识性归纳，非逐字原话。

本专题并不追求单一工具的绝对排名。讨论时先确定能力维度：依赖布局、受影响分析、任务图和缓存、发布编排、依赖边界导航、规模与治理。

| 维度 | pnpm workspace | Turborepo | Nx | Rush |
|---|---|---|---|---|
| 严格依赖布局 | 核心能力 | 依赖包管理器 | 依赖包管理器 | 对安装和治理有强约束 |
| Affected 分析 | filter | affected | nx affected | to / from / impacted-by |
| 任务图 / 缓存 | 脚本层实现 | 本地与远程缓存 | 图、缓存、云执行 | 分阶段构建与缓存 |
| 发布编排 | 常搭配 Changesets | 常搭配 Changesets | Nx Release | Change→Version→Publish |
| 依赖可视化 | 基础 | 较轻量 | Graph / 边界规则 | 另需约束工具 |

原讨论倾向 **Rush（有前提）**：当仓库规模、严格性和发布治理的收益超过初始学习成本时选 Rush；若首要目标是可视化依赖边界与云端分布式执行，可考虑 Nx。以上为讨论形成的工程观点，具体 API 与当前支持情况仍需以各家官方文档为准。
