# 课程档案：从第 1 课到第 14 课

> **来源说明**：这里根据当前可恢复的历史会话线索和已有《Promise 学习笔记》整理。记录中缺少部分题干与完整推理，未将“选项正确”推定为已掌握，也不将整理性解释冒充用户原话。

## 时间与环境

- **起始**：2026-10-12，用户要求“原理驱动 + 螺旋式”教学，JS 中级，已使用 `then/async-await`，学习环境含 Browser 与 Node.js。
- **截至 2026-10-24**：推进至第 14 课，并提出每周复习计划。课堂采取“每次一题，先回答、再诊断”的节奏。
- **2026-10-30**：反复制作微任务动画与 3D Promise 解谜游戏，要求机制准确、能够看懂以及完善的体验。

## 特别值得保留的真实推理线索

1. 第 6 课：用户正确指出 `async` 总返回 Promise，内部 throw 会导致拒绝；同时追问定时器 throw 如何被 catch 接住。
2. 第 11 课：用户曾解释 “any 只要一个 fulfilled 就成功，全部 rejected 才失败”；后续继续练习 `AggregateError.errors` 的输入顺序。
3. 第 13 课：用户明确意识到链式调用并非同一个 Promise，并指出代码没有显式 `return` 时隐式返回 `undefined`。
4. 第 14 课：用户指出 `then` 与 `get then()` 的同步边界需要区分，还将 `resolve(inner)` 视为 outer 跟随 inner 的过程；此处仍需精细校正**何时落实为 fulfilled**。
5. 螺旋复习：用户要求“先不公布答案，待作答后诊断漏洞，并逐渐提高难度”；该原则在下方自测题保留。

## 当前诊断维度

- 细分 `resolved` / `settled` / `fulfilled`。
- 区分 getter 的同步读取和 thenable Job 的异步调用。
- 分离反应注册、真正入队与执行三个时刻。
- 判断链上 `return`、`throw`、`finally` 和拒绝恢复对后继 Promise 的影响。
- 组合 API 的首个成功 / 首个落定 / 输入顺序结果 / 空数组边界。

## 下一次复习的判定标准

只选对不算过关。至少说明：**每个 Promise 的身份、状态、解决权是否锁定、微任务队列的变化**，再检查输出。遇到无法恢复的历史题目，使用独立新题重建测试，明确标注为“新编”。
