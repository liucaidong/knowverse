React Native 0.88.1：新架构时代的工程基线

以 v0.88.1 源码为时间锚点，区分架构里程碑与补丁版本演进。

源码基线：React Native v0.88.1（2026-11-10 核验）。0.88.x 是当前学习的稳定版本线；本文区分 0.88.0 功能变化与 0.88.1 补丁修复。

版本关键变化学习意义
0.76New Architecture 默认启用新项目开始以新架构为主
0.82第一个仅运行 New Architecture 的版本Legacy Architecture 不再是可关闭的并行运行模式
0.84Hermes V1 默认启用JS Runtime 实现持续演进
0.87Strict TypeScript API 成为默认 API类型 API 与工具链更严格
0.88.0Web-based Event Dispatching 默认启用；SceneDelegate 支持；Java TurboModule 支持 ArrayBuffer事件系统与二进制数据通路出现值得追踪的实现变化
0.88.1JSI RuntimeDecorator 转发补齐；Yoga flex-shrink 浮点残差修复；iOS 构建诊断改进补丁版修复运行时与布局边界，不代表架构重构

不要混淆三个时间尺度

架构世代：Legacy Bridge 与 New Architecture 的差异，决定核心抽象、渲染系统和 Native Module 机制。

版本迭代：每个 RN 版本会带来 Hermes、Metro、平台工具链和 API 的变化，不会重新定义 JSI / TurboModules / Fabric 的基本职责。

项目工程状态：Expo、Community CLI、SDK 和原生库影响真实兼容矩阵，必须按项目版本核验。

0.88.1 必须掌握的三个补丁级细节

  1. JSI RuntimeDecorator：0.88.1 补齐 createValueFromJsonUtf8、createArrayBuffer hooks 与 String::length 等转发。区分接口声明、装饰器转发与具体 JS 引擎实现。
  2. Java TurboModule ArrayBuffer：0.88.0 引入 ArrayBuffer 参数和返回值映射。非 owning buffer 是借用内存，方法返回后不可继续访问；需要保留时必须在方法内复制。
  3. Yoga 修复：0.88.1 修复 flex shrink 总量为正浮点残差时的异常行为。布局问题应同时看 ShadowTree 布局调用链与 Yoga 算法，不能把 Yoga 误认为平台 View Mount。

推荐学习顺序

  1. 用 Build / Startup / Runtime 理清生命周期。
  2. 用 JSI 和 TurboModules 理清 Native 调用边界。
  3. 用 Fabric 的 Render / Commit / Mount 理清 UI 更新。
  4. 用线程模型解释响应性。
  5. 最后再看 Release Notes、Gradle、CocoaPods、Metro 与 Hermes 的升级要求。
继续学习：返回专题全景 · 打开原理实验室 · 进入架构边界挑战
