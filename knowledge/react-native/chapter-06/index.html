线程模型、事件优先级与可中断渲染

理解 JavaScript Thread、UI Thread 和高优先级事件如何共同维护响应性。

React Native Renderer 不是“一条 JS 线程把所有事情做完”。关键是分清两条线程的职责，并理解事件优先级如何影响调度。

JavaScript Thread

执行常见 React render 阶段与布局相关工作。

UI Thread / Main Thread

唯一能够操作平台 Host Views 的线程。

sequenceDiagram
 participant JS as JavaScript Thread
 participant UI as UI Thread
 participant Views as Host Views
 JS->>JS: Begin Render (low priority)
 UI->>UI: Receive discrete user event
 UI-->>JS: Interrupt / schedule high-priority update
 UI->>Views: Apply host-view mutations
 JS->>JS: Resume or reconcile remaining work

Render 为什么能被中断？

Render 阶段可中断。当高优先级离散事件到达时，React / Renderer 可以中断当前 Render，并优先处理用户交互。特定场景下，高优先级 Render 工作可以在 UI Thread 同步执行。

不要把它扩展成“所有 Render 都在 UI Thread”。常见场景仍是在 JavaScript Thread 执行 Render；线程选择与事件优先级、渲染场景有关。

C++ State 更新是另一条路径

一些 Host Components 可能由 C++ 或平台层维护不直接暴露给 JavaScript 的状态，例如滚动位置。这样的状态更新可以跳过 React Render，直接参与 Commit / Mount 相关过程。

诊断问题的顺序

  1. 是 React state 更新，还是 Native / C++ State 更新？
  2. 当前处于 Render、Commit 还是 Mount？
  3. 哪条线程拥有当前操作？
  4. 是否有高优先级离散事件？
  5. 更新是否真正应用到 Host Views？
