Fabric：Render / Commit / Mount 的逐帧路径

从 React Element Tree 追到 C++ Shadow Tree，再到平台 Host Views。

Fabric 是 React Native 的新渲染系统。追踪一次 state 更新如何变成平台 View 更新，是理解它的最佳入口。

flowchart TD
 State[React state / props update] --> Render
 subgraph R[1 · Render]
  Render[React executes components] --> Element[React Element Tree]
  Element --> Shadow[Immutable C++ Shadow Tree]
 end
 subgraph C[2 · Commit]
  Shadow --> Layout[Yoga layout calculation]
  Layout --> Promote[Promote next tree]
 end
 subgraph M[3 · Mount]
  Promote --> Diff[Diff previous / next tree]
  Diff --> Mutations[Atomic view mutations]
  Mutations --> UI[Apply on UI Thread]
 end
 UI --> Pixels[Pixels on screen]

Render：React 逻辑与 Shadow Tree

React 执行组件逻辑，得到 React Element Tree。对 Host Components，Renderer 创建对应 C++ Shadow Nodes 并组织成 Shadow Tree。该树不可变；更新时通过克隆和结构共享构造新树。

Commit：布局与树提升

Commit 阶段安排 Layout Calculation，并使用 Yoga 计算 Shadow Nodes 的位置和大小。随后将新树提升为下一棵待 Mount 的树。

Mount：差异计算与平台视图

Mount 比较上一棵已渲染树与下一棵树，生成创建、更新、删除等原子 mutation，再应用到 Android / iOS Host Views。平台视图操作发生在 UI Thread。

牢记三个边界
  • Yoga 计算布局，不等于创建最终平台 View。
  • Commit 是提交与布局，不代表像素已经绘制。
  • Shadow Tree 是 C++ 渲染模型，不是平台 UIView / Android View 的副本。
