TurboModules 与 Codegen：从类型契约到原生实现

把 spec、生成代码、平台实现和模块注册拆成可审查的工程链路。

TurboModule 连接 React Native 应用与平台 Native 能力；Codegen 将类型化接口规格转换为跨语言 glue 和平台接口。

flowchart TD
 Spec[TypeScript / Flow Spec] --> Config[codegenConfig]
 Config --> Codegen[Codegen at app build]
 Codegen --> CPP[C++ glue]
 Codegen --> Android[Android Java interfaces]
 Codegen --> IOS[iOS Objective-C++ interfaces]
 CPP --> Impl[Native platform implementation]
 Android --> Impl
 IOS --> Impl
 Impl --> Registry[TurboModule Registry]
 Registry --> JS[JS API / TurboModuleRegistry]

1 · 声明类型化 spec

spec 描述 JavaScript 与 Native 之间的方法和数据类型。它是接口契约，不是原生功能本身。

2 · 配置 Codegen

在 package.json 中声明 codegenConfig，指定模块名称、spec 文件目录和 Android package 等。React Native 在构建 Android / iOS 应用时自动运行 Codegen。

3 · 编写原生实现

生成的 C++ glue 与平台接口帮助连接 JS 与原生实现；实际系统 API 调用、权限处理和错误映射仍由 Android / iOS 代码负责。

4 · 注册并从 JS 访问

模块通过 TurboModule Registry 暴露给 JS。访问模块和创建实例不是同一个动作；按需初始化可以减少不必要的启动成本。

验证清单

  1. 确认 Codegen 找到 spec 文件。
  2. 检查生成接口类型。
  3. 确认原生实现满足接口。
  4. 核对 JS Registry 与 Native 注册名称。
  5. 分别在 iOS 与 Android 构建和运行。
