# KNOWVERSE — 专题页启动资源与静态知识上下文

日期：2026-11-14

## 范围

12 个知识专题入口页、知识目录、专题文章页，以及共享站点启动资源。

## 审计发现

- 12 个专题入口页加载旧版 `knowledge-graph.js`（6,542 B）和 `knowledge-graph.css`（2,117 B）。知识目录和专题文章页也引用了旧样式；旧脚本在所有现有入口页提前退出，旧样式没有实际消费者。
- 新版知识上下文原先通过异步模块和四份完整源注册表插入页面内容，产生额外请求和首屏布局偏移。
- 上下文模块在专题入口和文章筛选中把 URL 字符串当作 URL 对象读取 `pathname`，触发 TypeError。异常只通过 console.warn 输出，原有全站路由 smoke test 未将其视为页面崩溃。
- 专题入口页异步插入关系区的实测 CLS 为 0.2179，超过 0.1 的目标线。

## 实施

1. 从知识目录、12 个专题页和专题文章页移除旧版脚本与样式引用，并删除无消费者的旧 JS/CSS。
2. 修复原动态上下文模块的 URL 字符串路径判断缺陷，确保源数据关系正确。
3. 新增 `scripts/knowledge_context_data.py` 与 `scripts/build-knowledge-context.py`，从 knowledge、works、learning-map、search-metadata 四份规范注册表生成静态 HTML，写入 99 个知识页面。
4. 移除浏览器端知识上下文动态模块及其全站启动导入。专题和文章页面不再运行时请求四份注册表，也不再异步插入关系区。
5. 内容验证器逐页重新生成期望 HTML 并比较，防止注册表变化后页面内容过期；README 与公共内容验证同步更新。

## 性能收益

- 每个专题入口页减少 8,659 B 未压缩旧资源（旧 JS 6,542 B + 旧 CSS 2,117 B）。
- 知识上下文由运行时四份 JSON 请求改为构建时静态 HTML；专题和文章页面不再请求 77,802 B 的四份源注册表，也不再下载上下文运行时模块。
- 关系区在首屏 HTML 中已经存在，消除异步插入造成的上下文布局跳动。

## 验收

- 12 个专题页均在 DOMContentLoaded 后已有唯一的静态 `.kv-topic-context`。
- 专题文章已有静态 `.kv-article-context`；知识目录保留静态架构概览。
- 所有上述页面均不请求旧版图谱 JS/CSS、知识上下文运行时模块或源注册表 JSON。
- Chromium 桌面 12 专题页 CLS 均低于 0.1；WebKit 移动端关键专题和文章页面无横向溢出且 CLS 低于 0.1。
- 内容注册表验证、架构验证和全站路由检查通过。
