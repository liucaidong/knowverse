# Phase C · Mac / iPhone Safari 实体设备验收

> 当前状态：自动化已覆盖 Chromium 双设备、WebKit iPhone 设备配置、空白设备 pull-only 冷恢复、离线 Outbox 与 CAS 冲突。此文档记录真正的 macOS Safari + iOS Safari 人工验收步骤；没有实体 iPhone 的测试记录不得标记为通过。

## 验收前提

- 使用已部署的同一 KNOWVERSE HTTPS 站点；不能用 `localhost` 代替跨设备测试。
- Supabase URL、Publishable Key 已配置；两端均通过 GitHub OAuth 登录同一个已加入 `private.authorized_users` 白名单的账户。
- 准备一台 Mac Safari 和一台真实 iPhone Safari。iPhone 建议使用一个干净的 Safari Profile 或从未访问过该站点的测试设备，不要为了测试清理日常使用中的个人网站数据。
- 记录部署 commit、Mac 型号与 macOS/Safari 版本、iPhone 型号与 iOS/Safari 版本、执行时间和测试账户的非敏感标识。不得记录 access token、refresh token、PKCE verifier 或密钥。

## A. Mac → iPhone 冷恢复

1. 在 Mac Safari 登录测试账户，打开一个有未完成进度的挑战，完成至少一次错误尝试，展开一个提示，然后停留在中间步骤，不要完成挑战。
2. 在同一账户下开始一项针对该知识点的复习，保持题目未提交；调整每日学习时长与专题偏好。
3. 打开全站账户面板，等待事件和档案文档同步完成。确认待上传事件、待同步档案均归零，记录当前设备 ID 与最近同步时间。
4. 在全新 iPhone Safari Profile 访问同一个 HTTPS 站点，使用同一 GitHub 账户登录。确认这是空白设备：此前没有挑战、活动复习会话或规划偏好。
5. 点击「从云端恢复」。预期账户面板反馈恢复事件数、恢复现场文档数、冲突数；该动作只拉取云端数据，不把本机内容先上传。
6. 按提示刷新页面。打开同一挑战，核对当前步骤、已完成步骤、尝试数、提示数和步骤输入数据；打开复习工作台，核对未完成复习现场可以继续；核对每日时长和专题偏好一致。
7. 刷新 iPhone Safari，再次进入相同页面，确认恢复结果由本机统一学习状态包持久化，不依赖仅存于当前 JS 内存的状态。

## B. iPhone → Mac 反向同步与离线恢复

1. 在 iPhone Safari 继续完成一条挑战或提交一次复习作答，确认本地事件数增加。
2. 开启飞行模式，继续完成一个可持久化动作。账户面板应显示离线状态；待上传事件保持不为零，刷新页面后本机状态仍在。
3. 关闭飞行模式，等待网络恢复，点击「立即同步」。预期 Outbox 只在服务端确认后减少至零。
4. 回到 Mac Safari 点击「立即同步」或重新打开页面，确认刚刚产生的事件、状态与学习规划可以拉取，事件没有重复计数。

## C. 并发修改与冲突保护

1. 两台设备先同步同一份挑战进度。
2. 断开其中一台网络，在两端分别推进到不同挑战步骤；先让 Mac 同步，再让 iPhone 恢复网络并同步。
3. 预期档案面板显示一项 CAS 冲突，且不会自动覆盖任一端。
4. 选择「保留本机版本」或「采用云端版本」之一，完成同步；两端再次同步后冲突应消失，最终 revision 与所选版本一致。

## D. 账户隔离与安全边界

1. 在测试浏览器 Profile A 登录账户 A 并产生本地学习数据。
2. 退出后尝试使用账户 B 登录同一 Profile；恢复操作必须拒绝将账户 B 的云端数据写入绑定账户 A 的本机学习档案。
3. 使用独立 Profile B 登录账户 B，应可正常恢复账户 B 自己的数据。
4. 确认 Supabase Auth session/PKCE 存储不出现在 `knowverse:learning-state` envelope 内。
