# KNOWVERSE 学习进度与知识掌握系统

版本：1.0.0 · 2026-11-01

## 目标

将知识专题、知识点、挑战体验、错误诊断、复习安排与再次验证连接为统一闭环。系统不以页面访问量或完成数量代替掌握程度；掌握状态只根据真实挑战证据产生。

## 架构

- 知识注册表：`content/knowledge.json` 定义专题。
- 掌握图谱：`content/learning-map.json` 定义可验证知识点、前置关系、布局和学习入口。
- 挑战注册表：`content/challenges.json` 定义挑战关卡，并通过 `competencyIds` 与掌握图谱连接；错误选项用稳定的 `gapId` 进行诊断。
- 统一事件模型：`assets/js/learning-progress.mjs` 负责事件生成、Local-first 存储、导入导出与掌握分析。
- 挑战引擎：`assets/js/challenge-engine.mjs` 在保存关卡进度时，计算差异并追加 attempt / hint / completed 事件。
- 展示层：`progress/index.html` 和 `assets/js/learning-progress-page.mjs` 提供学习驾驶舱、交互图谱、薄弱点、复习队列和事件历史。

## 核心事件

事件使用追加式日志，字段包括：

- `id`：由 challenge run、step、事件类型和序号组成的幂等 ID。
- `type`：`attempt`、`hint` 或 `completed`。
- `at`：事件时间。
- `topicId / challengeId / stepId`：内容来源。
- `competencyIds`：映射到一个或多个知识点。
- `gapId`：可选的稳定错误概念 ID。
- `scorePct / attempts / hintsUsed`：完成证据的透明评分字段。

重置挑战只创建新的 `runId` 并清理当前关卡状态，不删除学习事件历史。幂等 ID 避免重复保存产生重复事件。

## 掌握度与复习

完成证据的关卡得分沿用挑战评分规则：

`max(0, points - (attempts - 1) × attemptPenalty - hintsUsed × hintPenalty)`

掌握度使用最近最多 6 次完成证据的加权平均，并随证据时间衰减。错误尝试独立保留，用于识别尚未纠正的 gap。

- 待验证：没有完成证据。
- 需要补强：最近表现低于阈值，或加权表现明显偏低。
- 正在建立：有证据，但尚未达到初步掌握门槛。
- 初步掌握：加权掌握度达到 80，但证据数量或独立性尚不足。
- 稳定掌握：至少两次、跨两个日期的验证；加权分数不低于 85，最新分数不低于 80，最近两次均未使用提示。

初始复习间隔为：低于 60 分 1 天；低于 75 分 3 天；低于 90 分 7 天；90 分及以上 14 天。稳定掌握后可逐步延长，最长 30 天。该规则是可解释的产品策略，不是对记忆曲线的科学测量或诊断。

## 隐私与迁移

学习记录仅存储在当前站点来源的浏览器 localStorage，不进入公开仓库，也不发送到第三方服务。支持导出 JSON、在另一台设备导入并合并。静态 GitHub Pages 不提供用户账户或云同步，因此跨设备数据需要手动迁移。

## 当前接入范围

首批接入 Promise 的 5 个机制关卡、Monorepo 的 3 个工程关卡。其他知识专题可先显示在知识宇宙中，但在登记可验证挑战之前不计入掌握度分母。

## 验收标准

1. 挑战作答、提示、完成会生成统一事件。
2. 重载浏览器后事件和掌握状态仍可恢复。
3. 重置挑战不会删除历史事件；重新挑战可形成新一轮证据。
4. 同一事件重复保存或导入不会重复计数。
5. 错误 gap 在后续成功验证前保持为未解决；成功验证后自动解除。
6. 没有证据的知识点显示待验证，不记为 0 分或薄弱点。
7. JSON 导出后可在另一台设备导入合并。
8. Promise 与 Monorepo 的知识点映射、前置关系和本地路由通过 CI 校验。
