# Phase F — Proactive Learning Intelligence 产品设计

## 产品定位
Phase F 将 Phase E 的目标、计划、任务与 Agent 连接为持续学习决策闭环，不增加第四条顶层产品线。主动学习驾驶舱属于现有「学习成长」；Agent 是交互解释入口；Knowledge Map 是知识结构权威来源。

核心体验是回答：**现在最值得做什么、为什么、完成后如何验证、结果怎样改变下一步。**

## 用户流程
1. 用户打开学习成长，系统读取 Repository 事件、目标、偏好、任务和 Learning Intelligence。
2. 计算个体复习调度、遗忘风险、薄弱点趋势、目标偏差和目标完成时间范围。
3. 用算法版本及输入指纹验证派生投影；过期时重建并经 Repository/CAS 保存。
4. 到期复习通过既有 Task Orchestrator 幂等创建任务。
5. Next Best Action 对活动任务、复习、薄弱点、先修补齐和新知识排序并给出理由。
6. 用户打开既有课程、挑战或复习入口；taskId 可贯穿复习工作台。
7. Review Engine 追加评估事件，Orchestrator 按原证据链校验完成。
8. 新学习事件触发重新计算；计划调整仍先形成 proposal。

## 驾驶舱
- 今日行动：优先突出 1 项主行动，至多列出 3 项候选。每项显示类型、标题、关联知识、推荐理由、证据引用、预计时长、预期收益、延迟影响、置信程度和实际入口。
- 复习队列：待处理、逾期、重新学习、近期安排；显示 dueAt、稳定天数、间隔、掌握度、上次验证时间和风险原因。
- 风险与薄弱点趋势：新出现、改善中、持续存在、已解决、近期退化。没有充分事件时显示证据不足。
- 诊断：停滞、重复失败、复习积压、过载、提示依赖、目标偏差，必须给出原因、证据、影响和建议。
- 长期轨迹：范围内稳定掌握节点、按先修关系排序的专题阶段里程碑、阻碍、剩余工作量估算、预计日期范围、置信程度与影响变量。
- 学习轨迹时间线：真实记录目标创建/修改、计划提案/接受、任务开始/完成/失败/跳过、挑战作答、评估通过和复习；系统派生的风险快照显式标记为计算结果。

## 生命周期和控制权
复习状态为 new、learning、scheduled、due、overdue、relearning、stable。风险是调度信号，不是对学习者能力的绝对评价；不展示伪造遗忘概率。提示辅助不能替代无提示独立验证。目标完成继续遵循 Learning Intelligence 的稳定掌握条件。

系统可以自动检测、缓存、排序和创建到期复习任务，但不得自动修改目标偏好、取消任务或静默替换已接受计划。学习计划调整只能形成 proposal，用户接受后才生效。跳过/延期需记录理由。

## 运行边界
打开网站时恢复并补算；页面在线时合并事件通知触发计算；关闭浏览器后 GitHub Pages 不执行后台 JavaScript。本阶段不建设 Cron，也不声称浏览器关闭后仍运行。无历史证据时明确显示待验证与低置信度，不用模拟数据填充。
